# Local Development Setup

This guide takes you from a clean machine to a running RADAR development
environment. Total time: about 10 minutes, most of it Docker image pulls.

## Prerequisites

Install these yourself before starting. The bootstrap script checks for them
and tells you exactly what is missing, but it will not install them for you:

| Tool | Version | Notes |
|---|---|---|
| Python | 3.12 or newer | `python3 --version` to check |
| Docker | any recent | Docker Desktop on macOS, Docker Engine on Linux |
| Docker Compose | v2 plugin | ships with Docker Desktop; `docker compose version` to check |

Everything else — including `uv` (the Python package manager) and all Python
dev tools — is installed automatically by the steps below.

## Step 1: Bootstrap

From the repository root:

```bash
scripts/bootstrap.sh
```

What it does, in order:

1. Verifies Python >= 3.12, Docker, and the Compose v2 plugin. Fails with
   instructions if anything is missing.
2. Installs `uv` (via the official Astral installer, into `~/.local/bin`) if
   not already present.
3. Generates `.env` at the repo root with **random per-machine credentials**
   for Postgres, Vault, and Grafana. The file is created with permissions
   `600` and is gitignored. If `.env` already exists it is never overwritten.
4. Runs `make setup`, which:
   - `uv sync` — creates `.venv/` and installs the dev toolchain
     (pytest, pytest-asyncio, pytest-cov, ruff, mypy, pre-commit) from
     `uv.lock`
   - `uv run pre-commit install` — registers the git hooks

The script is idempotent: re-running it is always safe.

## Step 2: Add external credentials

Open `.env` and replace the `__SET_ME__` placeholders:

```
OPENAI_API_KEY=...      # your OpenAI API key
SLACK_BOT_TOKEN=...     # xoxb-... from your Slack app (needed from Phase 9)
SLACK_APP_TOKEN=...     # xapp-... for Socket Mode (needed from Phase 9)
```

These are not required to start the local stack — only the phases that call
LLMs and Slack need them.

**Never commit `.env` or paste its contents anywhere.** All generated secrets
are per-machine and can be regenerated by deleting `.env` and re-running
`scripts/bootstrap.sh`.

## Step 3: Start the stack

```bash
make dev
```

This starts six containers via Docker Compose
(`deploy/compose/docker-compose.yml`). All ports bind to `127.0.0.1` only —
nothing is reachable from your network.

| Service | Version | URL | Credentials |
|---|---|---|---|
| Postgres | 16 | `localhost:5432` | user `radar`, password in `.env` |
| Elasticsearch | 8.16.0 | http://localhost:9200 | none (security disabled, localhost only) |
| Kibana | 8.16.0 | http://localhost:5601 | none |
| Prometheus | v2.55.0 | http://localhost:9090 | none |
| Grafana | 11.3.0 | http://localhost:3000 | `admin`, password in `.env` |
| Vault | 1.18.0 (dev mode) | http://localhost:8200 | root token in `.env` |

First run pulls roughly 3–4 GB of images. Subsequent starts take seconds.

### Verify everything is up

```bash
docker compose --env-file .env -f deploy/compose/docker-compose.yml ps
```

All six services should report `healthy` (Elasticsearch and Kibana take
30–60 seconds). Or spot-check by hand:

```bash
curl -s http://localhost:9200/_cluster/health   # Elasticsearch
curl -s http://localhost:9090/-/healthy          # Prometheus
curl -s http://localhost:8200/v1/sys/health      # Vault
```

## Everyday commands

| Command | What it does |
|---|---|
| `make dev` | start the local stack (detached) |
| `make stop` | stop the stack, keep data |
| `make clean` | stop the stack and **delete all data volumes** |
| `make lint` | `ruff check` + `mypy` over the workspace |
| `make test` | run pytest |
| `make setup` | re-sync dependencies and reinstall hooks |

Data (Postgres tables, Elasticsearch indices, Grafana state) survives
`make stop` / `make dev` cycles. Only `make clean` wipes it.

## Git hooks

`pre-commit` runs automatically on every commit:

- **gitleaks** — blocks commits containing anything that looks like a secret
- **ruff** (lint + format) — auto-fixes style issues
- hygiene checks — trailing whitespace, YAML/TOML syntax, large files,
  private keys, merge-conflict markers

The first commit after setup is slow while pre-commit builds its isolated
hook environments; afterwards it is fast. Run against everything manually
with:

```bash
uv run pre-commit run --all-files
```

## Troubleshooting

**`make dev` says ".env not found"** — run `scripts/bootstrap.sh` first.
Compose refuses to start without generated credentials; there are no
hardcoded defaults.

**Elasticsearch is unhealthy or exits** — it needs ~1 GB free memory. On
Docker Desktop, raise the memory limit (Settings → Resources) to at least
4 GB for the whole stack.

**Port already in use** — something on your machine already occupies 5432,
9200, 5601, 9090, 3000, or 8200. Stop it, or edit the port mapping in
`deploy/compose/docker-compose.yml` (left side of the mapping only).

**I lost / corrupted my `.env`** — `rm .env && scripts/bootstrap.sh`, then
`make clean && make dev`. The `clean` is required because Postgres, Grafana,
and Vault keep the *old* credentials in their data volumes; regenerating
`.env` without wiping volumes leaves them out of sync.

**`uv: command not found` right after bootstrap** — the installer put it in
`~/.local/bin`, which may not be on your PATH in already-open shells. Open a
new terminal or `export PATH="$HOME/.local/bin:$PATH"`.
